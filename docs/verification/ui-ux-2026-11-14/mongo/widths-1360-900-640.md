# 1360 / 900 / 640 × 900 的 Mongo 文档区证据（T13）

证据类型：**headless 布局级**（不是原生像素截图，见 `README.md`）。每个宽度单独开一个 900 高的 GPUI 测试窗口，窗口里放真实的 `MongoPane`，由 `docs_states_and_cells_hold_at_1360 / _900 / _640` 在浅色/深色 × 紧凑/标准 四种组合下逐格断言。

## 采集方式

- 视口尺寸由窗口边界决定（`WindowOptions { window_bounds: WindowBounds::Windowed({width} × 900) }`），每个宽度一个用例、一个窗口，测试中不改运行期尺寸。
- 每格核对同一份清单：页面根宽、数据区宽、行宽、左栏形态、单元格点击、键盘等价、六态、下一步按钮。
- 断点用 `kit::NARROW_PAGE_WIDTH = 760`（与设计 S7.3 的 ≤960 收侧栏、≤640 覆盖内容区一致；本页取 760 作为"左栏改抽屉"的门槛）。

## 滚动职责（本任务的核心结论）

- **页面级**：`#mongo-pane` 是 `.relative().flex().min_w(px(0.)).overflow_hidden()`，只负责分栏；工具条 `flex_wrap`、面包屑 `flex_wrap` + 名称截断，长库名/集合名不会把页面撑宽。
- **内容级**：`#mongo-docs` 是唯一滚动容器。有行时纵向 + 横向都可滚（`overflow_y_scroll().overflow_x_scroll()`）；六态的其它分支只纵向排布，且状态块按容器宽换行（`state_block` 自带 `min_w(0)`）。
- **左栏**：宽窗口在布局里（`.w(px(header_h*4 + pane_pad))`，内部 `overflow_y_scroll`）；窄窗口是 `absolute` 抽屉 + 遮罩，覆盖内容区而不挤压文档表。

因此 900 与 640 下"七列 ≥ 120px 一行 964px"的超宽部分，表现为**文档数据区内部的横向滚动条**，页面本身在两个宽度下都没有横向滚动——这与探索记录里"Mongo 的 overflow_x_scroll 是数据区域自身滚动，应按页面级与内容级区别核对"的结论一致。
