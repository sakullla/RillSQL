# 1360 / 900 / 640 × 900 的关系图证据（T10）

证据类型：**headless 布局级 + 原生行为级**（不是原生像素截图，见 `README.md`）。三个宽度各自开一个 900 高的 GPUI 测试窗口，窗口里放真实的 `DiagramPane`（`PaneHost`），由 `diagram_four_states_and_keyboard_hold_at_1360 / _900 / _640` 在浅色/深色 × 紧凑/标准 四种组合下逐格断言。

## 采集方式

- 视口尺寸由窗口边界决定（`WindowOptions { window_bounds: WindowBounds::Windowed(640/900/1360 × 900) }`）。测试平台的 `Window::resize` 实测不改视口，所以每个宽度单独一个用例、单独开一个窗口，全程不调用 `resize`（源码里已无该调用）。
- 每个格子都按同一份清单核对：卡片元素、页头工具条所在行、放大按钮、Tab+Enter、四种状态。
- 断点：`kit::NARROW_PAGE_WIDTH = 760`，与设计 S7.3 的 `≤640` 与 `≤960` 档位不冲突（本页 640 换行，900 仍单行）。

## 逐宽度结果

| 检查项 | 1360 | 900 | 640 |
| --- | --- | --- | --- |
| 页头 | 单行：标题 + 180px 搜索框 + 缩放/100%/适应/返回 | 单行（同上） | **两行**：标题行 + `diagram-tools` 行（搜索框 `flex_1` 占满，缩放/100%/适应/返回在右） |
| `diagram-tools` 元素 | 不存在 | 不存在 | 存在 |
| 表卡片（`diagram-card:orders` / `:customers`） | 存在 | 存在 | 存在 |
| 放大按钮（`diagram-zoom-in`）点击后 `zoom = 1.1` | 通过 | 通过 | 通过 |
| Tab 停在卡片上按 Enter → 产生“打开表数据”请求 | 通过 | 通过 | 通过 |
| 空图：`empty-state` + `state-action` + `diagram-read-again` | 通过 | 通过 | 通过 |
| 失败：`error-state` + `error-state-detail` + `diagram-retry` | 通过 | 通过 | 通过 |
| 无目标：`empty-state` + `state-action`，且**没有** `error-state` | 通过 | 通过 | 通过 |
| 读取中：`loading-state` | 通过 | 通过 | 通过 |
| 页面横向滚动 | 不出现（画布在 `overflow_hidden` 容器里按列布局，卡片位置由 pan/zoom 决定，不撑宽页面） | 同左 | 同左（页头两行后不再有单行超宽） |

四种主题/密度组合（浅·紧凑、浅·标准、深·紧凑、深·标准）在三个宽度下都是同一份结果。

## 窄宽的具体处理

- 640 时标题行仍走 `kit::page_header`（高度 `Metrics::header_h`、左右边距 `Metrics::for_viewport(640).page_pad` 钳到紧凑档），第二行是 `diagram-tools`：`.flex().items_center().gap(6.).px(page_pad).pb(8.)`，搜索框 `.flex_1().min_w(0.)`，缩放/100%/适应/返回依次排在右边。
- 卡片布局不变（列宽 220、列间距 90），缩放比例与平移照旧由 pan/zoom 控制，窄窗不重新排图（不重做图功能）。
- 卡片菜单条（`diagram-card-menu`）在窄宽隐藏右侧键位提示（`diagram-card-keys`），保留关闭按钮，避免提示被挤断行。
