# 1360 / 900 / 640 查询错误场景证据（T6 · Outcome 4）

## 采集方式

- 用例：`app::views::query::tests::rewritten_error_evidence_holds_at_1360_900_and_640`
- 窗口：GPUI 测试窗口，三档 1360×900 / 900×900 / 640×900（`open_sized`，与既有 `open` 同一套服务与环境，只是尺寸可配）。
- 场景：草稿为两条语句 `select 1;\nselect * from logs where;`，第二条被自动追加 ` LIMIT 101` 后报 `near "LIMIT": syntax error`（驱动不给位置，模拟 SQLite），界面拿到 `sql`/一批 `sent_sql`/`rewrite`。
- 每档断言（全部通过）：
  1. `query-rewrite-note` 可见且文本含「自动改写」与「LIMIT 101」；
  2. `query-rewrite-sql` 的可访问名等于 `select * from logs where LIMIT 101;`；
  3. `query-error-jump-panel` 可见，`query-error-summary` 只有「失败」（长错误不在头部重复）；
  4. 点击定位后编辑器选中的正是 `select * from logs where;`，与错误标记范围一致。

## 结果

| 宽度 | 改写说明 | 实际执行语句 | 定位按钮 | 跳转选中 |
| --- | --- | --- | --- | --- |
| 1360×900 | 可见 | `select * from logs where LIMIT 101;` | 可见 | 整条失败语句 |
| 900×900 | 可见 | 同上 | 可见 | 整条失败语句 |
| 640×900 | 可见 | 同上 | 可见 | 整条失败语句 |

同文件的其余用例补足了同场景的其它分支（自动改写叙述、手写 LIMIT 对照、消息页只出现一次）。
