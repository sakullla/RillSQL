## 2. 三态语义的落地细节

- 同一份排版函数 `state_block`，三类只换图标色调：无数据用强调浅底（`accent_soft`/`accent_text`），无命中用中性底（`hover`/`text_muted`，不报警），错误用危险色（`danger_soft`/`danger`）。
- 主操作用调用方给的元素，不内建按钮：底座不知道「新建连接」还是「清除筛选」，只保证位置（与标题文字同列）与可点。
- 空态不再保留内容区骨架：三态返回的是可替换内容区的整块，调用方把它放进原内容位置（表格头不留在空态上方）。
- 加载优先于空：`loading_state`/`skeleton_state`/`inline_loading` 与空态是互斥分支，页面按「加载中 → 骨架 → 内容或空态」排列，不叠两层。

## 3. 未解决事实

1. **原生像素证据未取得**：本任务运行环境没有可用原生窗口/截屏通道，`浅/深色 × 紧凑/标准` 的底座截图未生成。已有证据是源码级断言 + headless 布局断言（见 `theme-density-matrix.md`、`test-receipts.md`）。需要 Delivery Owner 在集成 candidate 上跑原生 `rillsql` 补齐，不能用 2026-11-11 的历史 PNG 顶替。
2. **页面仍在自绘三态**：`app/` 下还有直接用 `Spinner`、自绘空态文案的调用点（探索阶段已逐页记录）。本任务只提供唯一入口，没有加源码扫描强制替换——现有合法的行级 Spinner 调用（树节点、按钮）会误报，真正收敛要在各页迁移时逐处核对。因此「页面不再发明另一套三态」在此刻是**提供入口 + 记录归属**，不是已完成的全量替换。
3. **system 主题运行中跟随 OS 外观**：本任务未覆盖，探索阶段也只在创建时核实过，属未验证能力。
4. **reduced-motion**：应用侧没有动画实现，新增的骨架与三态都是静态色块，没有可归零的位移动画；GPUI 是否暴露系统 reduced-motion 读取仍未核实，本轮不因此新增装饰动画。
5. **`empty_state` 的布局变化会立刻影响现有调用点**：连接页、关系图、Mongo、Redis、管理页的空态从居中变左对齐。这是本任务的目标，但它们在各自任务重排面板前会出现「贴左但外层仍居中包裹」的过渡形态；`connections_empty_state_wraps_inside_its_panel_at_every_width` 已在本轮回归中通过（1360/900/640 不越界）。
