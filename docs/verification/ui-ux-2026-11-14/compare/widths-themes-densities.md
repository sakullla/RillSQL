# 三档宽度 × 双主题 × 双密度（T11）

用例：`app::views::compare::workbench::sides_reflow_at_1360_900_and_640_in_both_themes_and_densities`
（```cargo test --manifest-path src-tauri/Cargo.toml --locked --lib app::views::compare::workbench::sides_reflow -- --nocapture```）

做法：GPUI 无头窗口（`gpui_kit::open_window`），窗口高固定 900，宽分别 1360 / 900 / 640；
每个宽度下先 `kit::apply_theme(dark, cx)` + `Metrics::publish(cx)`，再渲染一帧，
用 `window.find(id).bounds()` 取两张侧卡片与其首行候选连接的实测几何。
断言：两侧卡片与候选连接都留在窗口内；1360 两张卡片顶部同高、右侧卡片在右侧；
900/640 两张卡片同列、右侧卡片在下方。

## 读数说明

- 1360：两张卡片 top 都是 56（紧凑）/66（标准），右侧卡片 x 落在 `基准右边界 + 间距 + 交换按钮` 之后 → 并排成立；
  首行候选连接同一 y（99.5 / 113.5），两侧行对齐。
- 900 / 640：两张卡片同一 x（900 紧凑 16、640 紧凑 16），对照卡片 top = 基准卡片 bottom + 卡片间距 + 居中交换按钮行。
  实测 900 紧凑：基准 56+103.5=159.5，对照 199，差 39.5px 就是间距与交换按钮那一行的占位；
  首行候选连接同样上下错开一个卡片高 → 竖排成立。
- 640：页面水平边距收到紧凑 16；竖向不钳制。所有元素 `x + width ≤ 视口宽`，没有横向溢出。
