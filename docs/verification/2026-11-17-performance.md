# v0.2.39：高延迟目录、补全与界面性能

基线：拉取后的 main `1bf2b1c`（v0.2.38）。用户报告 MySQL 已连接后长时间停在“读取中”，环境有几十个库、数千张表；随后要求检查常用页面、代码补全、命令面板的性能与内存。

## 修复与边界

- MySQL/MariaDB 建连验证使用目录池，库列表可复用已认证连接；执行池在第一次执行时建立独占连接，事务、USE 和会话变量仍由该连接承载。取消编号由执行器取得连接时从握手更新，不能误杀目录连接。
- 导航分组只发一条有界查询，取 `page_size + 1` 判断续页，不再先 COUNT，也不读取 `table_rows` 统计。不确定总数显示“已加载数+”，读到末页才显示确切总数。比较/导出等需要原计数语义的接口保持原逻辑。
- MySQL 补全用一次轻量名字查询读取当前库的表、视图、例程、触发器和事件，不逐类计数，不再把 5,000 个对象的截断页缓存成完整目录。库名采用 UTF-8 十六进制字面量，覆盖引号、反斜杠、问号和 Unicode 名字。
- 补全任务排队时不因经过 30 秒而重复派发；刷新、断开和页面实体销毁会取消旧任务，迟到结果不回填。整库名字缓存最多保留最近读取的 8 个库；断开/刷新释放相关列、注释和外键缓存。
- 补全快照按目标、可用状态和元数据版本更新，滚动、光标移动、重绘不再重建整个目录。未展开到的表也可使用按 SQL 引用读取的列补全。工作台目录索引同步也按版本进行。
- SQL 大纲刷新不再复制整个 TabState（包括查询结果、固定结果），只有 SQL、方言或结果代次改变才重新解析。格式化、展开星号、执行计划与发起执行也不再为读取草稿而复制结果集。
- 命令面板先按范围构建候选，筛选/排序移动条目所有权，省去多轮目录复制；超过 200 个候选时只渲染可见行。保留全部搜索结果及 Home/End 导航，没有截断候选来提高速度。
- 网格多格计数按矩形并集减去洞计算，不再展开为逐格集合；超过 4,096 格仍沿用原规则，不进行数值聚合。测试覆盖十亿格逻辑选区及重叠、减选和越界裁剪。
- Redis SCAN 续页改为移动旧数据并按哈希位置合并，保留顺序和“重复键最后结果生效”，省去全量复制和逐项线性查重。MongoDB 表格一行只解析一次 JSON，不再为每个格子的文字和徽标各解析整篇文档。ER 图生产渲染不生成仅供测试使用的隐藏全文摘要。

检查了共享网格、结构/管理、比较、历史、导出及文档/键浏览的渲染和请求路径。本次修改集中在上面列出的可确认开销；没有宣称每个页面都经过独立网络压测，也没有改写数据库中的业务 SQL。

### 高延迟 MySQL 协议验证

`scripts/verify-catalog-mysql.py --delay 2 --databases 40 --objects 6000`，mysql-mimic 3.0.5，仅监听 loopback；每条查询（包括连接设置查询）延迟 2 秒。Rust 使用真实 mysql_async 网络驱动。模拟目录每库 6,000 张表，概要仅列 40 个库，不枚举所有库中的表。

运行：`cargo test --manifest-path src-tauri/Cargo.toml --locked --lib mysql_large_catalog_fast_path_fixture -- --ignored --nocapture`。

| 读取 | 实测时间 |
| --- | ---: |
| 建连验证 | 4.08 s |
| 40 个库概要 | 2.00 s |
| 第一页（池此时额外创建一个连接） | 4.01 s |
| 复用连接后的每页（100 个对象） | 2.00 s |
| 当前库完整 6,000 个名字补全 | 2.02 s |

验证第一页、第二页、末页和越界空页，并检查补全包含第 6,000 个对象。[完整输出](performance-2026-11-17/mysql-latency-2s.txt)。池需要新连接时仍须支付握手和初始化开销，没有宣称任意冷读取只需一次往返。

另运行 `mysql_lazy_navigation_latency_fixture`，经 GPUI 展开库和表分组、续页、连续 20 次刷新，验证旧页取消、刷新合并和加载状态收尾。旧专项硬编码每页 100，而当前产品默认是 500；已在测试里显式设置 100。

这是协议模拟，未访问用户业务库；不测量真实服务器的权限扫描、锁等待、丢包或 SSH 建连耗时。

### 大纲刷新专项内存与 CPU

同一 debug 测试程序，10,000 行 × 1,024 字节正文，另固定同一结果，连续刷新 100 次。旧路径在测试中重放 v0.2.38 的 TabState 深复制和解析；新路径调用实际修复后的 `refresh_outline`。`/usr/bin/time -l` 测量独立测试进程 RSS；时间只计刷新循环。

| 指标 | 旧路径 | 修复后 |
| --- | ---: | ---: |
| 100 次刷新 | 263,709 µs | 147 µs |
| 进程峰值 RSS | 66,682,880 B | 44,810,240 B |

[旧路径输出](performance-2026-11-17/outline-before.txt)、[修复后输出](performance-2026-11-17/outline-after.txt)。这是单次合成专项结果，受调度/分配器影响；不能外推为整应用内存降幅或所有操作的提速比例。

复测：先构建测试程序，再直接运行输出的测试可执行文件 `benchmark_outline_refresh_without_result_copies --ignored --nocapture`；设置 `RILLSQL_BENCH_BASELINE=1` 重放旧路径，不设置时使用新路径。
