# 需求：澄库 · RillSQL

日期：2026-10-14

## 一屏摘要

- 目标与使用者：为个人开发者提供简单、轻量、高颜值的 SQL 桌面管理工具，应用命名为“澄库 · RillSQL”（R1）。
- 兼容范围：Windows、macOS、Linux；MySQL/MariaDB、PostgreSQL、SQLite，核心操作保持一致并尊重数据库差异（R2）。
- 连接范围：连接管理、直连、TLS、SSH 隧道及 SQLite 本地文件（R3–R5）。
- 日常范围：库表查找、结构查看、SQL 编辑与执行、查询历史、数据浏览和增删改、CSV 导出（R6–R11、R17）。
- 完整管理范围：可视化建表、修改字段、管理索引与外键，以及明确确认后的删表操作（R12–R16）。
- 关键边界：结构变更先预览 SQL；有损操作明确提示；无法唯一定位的行不直接编辑；取消、断连和提交失败如实反馈，不承诺所有操作均可回滚（R8、R11、R16）。
- 成功标准：三平台通过相同核心场景验收；大量对象与结果不会无上限自动加载，执行期间仍可操作界面；明暗主题与关键快捷操作完整（R2、R18、R19）。
- 默认假设：桌面三平台、个人开发者定位及克制紧凑的界面沿用已提交摘要；具体系统/数据库版本矩阵与性能测量环境需在研发验证时记录，不虚设数值指标（R2、R18、R19）。
- 不做事项：AI、云同步、团队权限、NoSQL、复杂关系图、备份恢复与运维监控（R20–R25）。

## 完整需求

### R1 产品名称与定位

行为：应用命名为“澄库 · RillSQL”，中文简称“澄库”，英文名“RillSQL”。“澄”表达清晰，“库”指数据库；Rill 意为细流，呼应轻量定位。默认面向个人开发者日常连接、查询、编辑数据及维护表结构的场景。

适用与失败边界：产品名称用于应用标题、关于信息和交付说明；命名不表示商标、域名或应用商店名称已经核验或注册。产品目标为桌面 SQL 管理工具。

验收：

- 启动应用及打开关于信息时，能够识别 RillSQL 名称；交付文档中的中英文名称一致。
- 用户能够通过应用进入连接、查询、数据编辑与表结构管理流程。

### R2 跨平台与数据库兼容

行为：在 Windows、macOS、Linux 提供桌面应用，支持 MySQL、MariaDB、PostgreSQL 与 SQLite；各平台提供本需求中的相同核心能力。数据库特有能力按实际支持情况展示。

适用与失败边界：MySQL 与 MariaDB 分别验证，不因协议相近而宣称完全等价。跨平台不等于支持所有历史系统版本或所有 CPU 架构；交付时明确列出实际支持、验证的系统、架构和数据库版本。遇到不支持的版本或结构操作时，显示具体限制，不伪装执行成功。

验收：

- 在交付声明支持的三平台环境中，分别完成各数据库的连接、查询、数据编辑、结构管理及导出场景。
- 交付物附实际验证矩阵，能够区分已验证组合、未支持组合及数据库能力限制。
- 某数据库不支持的结构选项不会作为可成功执行的通用选项出现。

### R3 连接管理与本地数据库打开

行为：允许创建、编辑、测试、保存、连接、断开及删除连接配置。远程数据库支持填写连接参数并直接连接；SQLite 支持选择现有本地数据库文件。查询和编辑上下文持续显示连接与数据库身份。

适用与失败边界：删除连接配置不删除数据库或 SQLite 文件。允许不保存密码；选择保存时，不以明文写入普通配置或日志。参数缺失、认证失败、连接超时、文件不存在或没有访问权限时，显示可理解的失败原因，不产生虚假的已连接状态。

验收：

- 保存一个有效远程连接，重启后可以重新连接；打开有效 SQLite 文件后可以浏览其中的表。
- 使用错误密码、不可达地址或无权限文件时，收到相应错误且仍可修改配置。
- 删除连接后，数据库内容或本地文件仍然存在；检查普通配置及错误日志，不出现保存的明文密码。

### R4 TLS 加密连接

行为：MySQL/MariaDB 与 PostgreSQL 连接可配置 TLS；启用证书验证时依据指定或系统信任的证书验证服务端。数据库或环境需要时支持提供客户端证书材料。

适用与失败边界：TLS 仅适用于远程数据库连接；SQLite 不展示无意义的 TLS 配置。证书过期、不受信任、主机名不匹配或证书材料不可读时，不静默降级为不验证或未加密连接。

验收：

- 使用有效证书配置能够建立加密连接；连接信息能够识别 TLS 状态。
- 开启验证后连接证书不匹配的服务端时，明确失败且不以降低验证级别自动重试。

### R5 内置 SSH 隧道

行为：远程数据库连接支持通过单个 SSH 跳板机建立隧道，配置跳板机、SSH 用户和目标数据库地址；支持密码或私钥认证，并处理私钥口令。连接操作统一管理数据库连接与隧道生命周期。

适用与失败边界：首版以单跳 SSH 为边界，不扩展为复杂多跳或企业统一认证管理。首次遇到未知主机密钥时展示指纹并要求确认；已记录主机密钥发生变化时明确阻止静默连接。区分 SSH 认证、隧道建立和数据库认证失败，错误信息不泄露凭据。

验收：

- 在数据库只能从跳板机访问的环境中，分别用密码和私钥建立连接并执行查询。
- 输入错误 SSH 凭据、错误数据库凭据时，能够区分失败阶段并修改配置重试。
- 主机密钥变化时无法未经确认继续；主动断开连接后相关隧道释放。

### R6 库表导航与结构查看

行为：按数据库实际层级展示数据库、schema 与表，支持按名称搜索表、刷新对象列表，以及查看字段、类型、空值约束、主键、索引、外键和数据库可提供的建表 SQL。

适用与失败边界：不将某一种数据库的 schema 模型强加给其他数据库。元数据权限不足、对象已被外部删除或结构加载失败时，提示原因并允许刷新；不将加载失败显示成“没有表”。

验收：

- 在包含多个同名表、不同 schema 的数据库中搜索后，结果保留足够的层级信息供准确选择。
- 创建包含主键、索引和外键的测试表，详情与数据库实际结构一致。
- 外部删除一个已打开的表后刷新，显示对象失效状态且不误操作其他表。

### R7 SQL 编辑工作区

行为：提供多标签 SQL 编辑、语法高亮、基础关键词与当前连接下表名/字段名补全，以及整段或选中 SQL 的执行入口。标签清楚关联连接与数据库。

适用与失败边界：补全以当前数据库方言与有权限读取的元数据为依据；无法取得元数据时仍允许输入和手动执行 SQL。切换连接不静默丢弃文本或将旧连接的对象建议误当作新连接事实。

验收：

- 同时打开两个连接的 SQL 标签，补全及执行对象分别对应各自连接。
- 在包含多条语句的编辑区选中一条后执行，仅向目标数据库提交选中内容。
- 元数据读取失败时编辑区仍可输入，且不会展示无法完成的补全为成功结果。

### R8 SQL 执行、结果与取消

行为：执行 SQL 后展示运行状态、结果或影响行数、耗时与数据库错误。支持请求取消正在运行的查询；执行期间允许切换标签和编辑其他草稿。对明确执行的多条 SQL 按顺序处理，遇到错误停止后续语句并显示已完成部分。

适用与失败边界：取消请求不等于数据库已停止执行，只有取得相应结果后才标记已取消。断连或超时后若不能确定写入是否完成，应标记结果未知，不自动重放 SQL。连接失败或断开不清空编辑草稿。手写 SQL 按数据库权限与事务语义执行，不承诺通用解析器可判断全部风险或自动回滚。

验收：

- 执行成功查询、语法错误及权限不足语句，分别展示正确结果或对应错误。
- 执行耗时查询后请求取消，界面能够区分请求中、取消成功和取消失败；可同时切换其他标签。
- 执行期间断开网络，保留 SQL 文本，并明确报告失败或结果未知，不自动再次执行写入。
- 多语句中的第二条失败时，报告第一条实际结果，第三条不继续执行。

### R9 本地查询历史

行为：记录已发起执行的 SQL、执行时间和连接身份，支持查看、搜索、重新载入编辑区及清空历史。

适用与失败边界：历史仅保存在本机，不因打开历史而自动执行语句。原连接已删除或不可用时，允许恢复文本并选择连接，不静默转向其他数据库。连接密码不附加到历史元数据；用户 SQL 本身可能含敏感内容，允许主动清空。

验收：

- 执行一条具有唯一文本的查询后，可以搜索到对应历史并恢复文本。
- 从历史载入 DELETE 等写入语句时，数据库不会在用户再次执行前发生变化。
- 清空后，历史界面和应用维护的历史记录中不再包含对应条目。

### R10 数据浏览、筛选与大结果集

行为：表数据和查询结果以表格展示，支持区分 NULL 与空字符串、复制数据，以及表浏览中的筛选和排序。默认限制一次加载的数据量，并允许明确地继续读取；展示已加载数量和截断状态。

适用与失败边界：不默认读取整张大表或完整大字段以填满界面。筛选、排序的作用范围必须明确，不将当前页排序伪装为全表排序。数据加载失败时保留筛选条件并显示错误；大字段可按需查看而不能伪装成完整值。

验收：

- 浏览记录数超过默认加载上限的表时，初次读取受限，界面提示存在未加载数据；用户可继续读取。
- 对含 NULL、空字符串、中文及长文本的表进行浏览和复制，能够正确区分与还原相应值。
- 设置筛选和排序后，结果符合所标明的作用范围；请求失败不会显示为“无匹配结果”。

### R11 表数据增删改

行为：在基础表浏览界面支持新增记录、修改单元格和删除记录；提交前可查看待提交变更并放弃修改。成功提交后更新显示，失败时保留可定位的错误与待处理内容。

适用与失败边界：更新和删除必须能够通过主键或其他可靠唯一标识定位目标行；无法唯一定位时禁用对应行内操作。联表、聚合等任意查询结果首版不承诺可编辑。唯一性、类型、外键或权限错误不得伪装为成功；部分成功或影响行数异常时清楚报告实际结果，不承诺全部操作自动回滚。

验收：

- 对有主键的表新增、修改和删除一行，提交后重新查询，结果符合预期；放弃未提交变更时数据库保持原值。
- 对无可靠唯一标识的重复行，不能通过行内修改或删除误伤多行。
- 提交违反唯一约束的数据时显示数据库错误，界面不将失败数据标记为已保存。

### R12 可视化创建与删除表

行为：提供可视化建表入口，配置表名、字段、类型、空值约束、默认值和主键；通过 R16 的预览确认后提交。允许删除选定表，并明确显示目标连接、库/schema 与表名。

适用与失败边界：名称、类型和默认值按目标数据库规则校验。重名、权限不足或依赖阻止操作时显示实际错误；删除表不隐式扩大为级联删除其他对象。索引与外键管理分别按 R14、R15 验收。

验收：

- 在每种支持的数据库中创建包含主键与可空字段的表，刷新后查看到一致结构并可插入合法记录。
- 创建重名表时收到明确错误，已有表及数据不被覆盖。
- 取消删表确认后表仍存在；明确确认后仅按预览范围删除目标对象。

### R13 可视化字段修改

行为：支持为现有表新增、重命名、修改和删除字段，包括数据库允许的类型、空值约束和默认值变更。变更经 R16 预览确认后执行。

适用与失败边界：基于实际数据库能力处理差异。SQLite 等场景如涉及表重建，必须提前显示影响；不能可靠保留原有数据、索引或约束时，应阻止该变更并解释限制。类型转换、非空约束或删除字段可能损失数据时明确提示，不以自动清空或截断数据掩盖失败。

验收：

- 对含既有数据的表完成合法新增字段和重命名，原有数据仍可按新结构访问。
- 将包含 NULL 的字段改为非空且无法满足约束时，操作失败或在提交前被阻止，并显示原因。
- 删除字段前可以确认影响；取消时字段与数据保持不变。
- 对涉及重建的合法变更，执行后检查记录及应保留约束；无法可靠处理的组合不得给出虚假成功。

### R14 索引管理

行为：查看并可视化创建、删除普通索引和唯一索引，支持多列及列顺序，经 R16 确认后执行。

适用与失败边界：数据库隐式或约束依赖索引须标明关系，不作为可无条件删除的独立对象。首版不以覆盖全部数据库专有索引类型为验收条件；不支持的类型可以查看已有信息，但不能生成错误变更。

验收：

- 创建两列联合索引后，数据库实际列顺序与配置相符；删除普通索引后刷新显示一致。
- 对重复值创建唯一索引时显示失败，原有数据不被自动清理。
- 操作受约束依赖的索引时，显示限制或数据库错误，不静默删除依赖约束。

### R15 外键管理

行为：查看、创建和删除数据库支持的外键，选择本表字段、目标表字段及允许的引用动作，并支持复合外键；操作经 R16 确认后执行。

适用与失败边界：目标字段、类型、数据或存储引擎不满足外键条件时，明确报告原因；不靠静默关闭约束检查来宣称创建成功。SQLite 如涉及重建，遵守 R13 的数据与约束保留边界。数据库配置影响外键是否实际生效时，应显示该状态。

验收：

- 为合法父子表创建外键，数据库元数据与界面定义一致，并按已生效的约束处理非法引用。
- 存在不符合外键的数据时，创建操作失败或被阻止，不能只在界面显示一个未生效的外键。
- 删除外键后，移除的是指定约束，不隐式删除父表、子表或记录。

### R16 结构变更预览与结果反馈

行为：可视化结构操作提交前展示目标连接、对象、计划执行的 SQL 与可识别影响，并允许取消。涉及删除、数据丢失或表重建时，额外明确提示其影响；执行后显示成功、失败、部分完成或结果未知。

适用与失败边界：预览针对应用生成的结构操作，不宣称能够识别任意手写 SQL、存储过程中的全部风险。数据库 DDL 事务能力不同，不统一承诺回滚。执行状态不确定时不自动重复提交，需先检查数据库实际状态。

验收：

- 建表、字段修改、索引及外键变更均可在提交前查看对应 SQL，取消后没有数据库变更。
- 删除或重建相关流程明确显示受影响对象及风险，用户确认前不开始执行。
- 模拟多步操作中途失败，界面能够区分已完成与未完成部分；断连不能误报为全部成功或已全部回滚。

### R17 CSV 导出

行为：将表浏览数据或查询结果导出为 CSV，在开始前明确导出的筛选条件与数据范围；支持正确处理分隔符、引号、换行及中文内容。执行中显示状态，完成后报告实际导出数量。

适用与失败边界：仅导出已加载数据时明确说明，不能将截断结果标记为全量导出。NULL 与空字符串的表示规则在导出时可见。路径不可写、空间不足、读取失败或用户取消时显示未完成状态，部分文件不得伪装为完整结果。CSV 导出不等于数据库备份。

验收：

- 导出包含逗号、双引号、换行和中文的测试结果，用 CSV 解析器读取后得到对应字段值。
- 对已筛选且存在未加载记录的数据导出，文件数量与界面声明的范围一致。
- 目标路径不可写或中途取消时，界面不显示导出成功，并说明文件是否部分生成。

### R18 清晰、克制的界面体验

行为：采用紧凑清晰的表格、克制的工具栏与一致的导航层级，提供明暗主题和核心键盘操作；连接、表对象、SQL 标签与执行状态有稳定可辨的展示。默认视觉方向强调内容可读与日常操作效率。

适用与失败边界：“高颜值”不以装饰数量代替可用性。颜色不能作为区分连接或错误的唯一信息；系统缩放、窗口调整、长对象名或错误文本不应遮挡关键操作。快捷键使用对应平台习惯，并在界面中可发现。

验收：

- 在两种主题中完成连接、找表、执行查询和编辑数据，文本、焦点、选中项及错误状态清楚可辨。
- 可通过键盘完成打开查询标签、执行 SQL、查找对象等核心操作，并能找到对应快捷键提示。
- 在声明支持的显示环境中调整窗口、切换系统缩放，关键按钮仍可触达；长名称可查看完整内容。
- 切换不同连接标签时，能够凭文字识别当前执行目标，不依赖颜色猜测。

### R19 轻量与响应性

行为：启动和基本编辑不依赖登录云服务；连接、查询、元数据读取和导出期间界面保持可操作。对对象列表、结果和大字段控制自动加载规模，用户可以理解加载状态并主动继续读取。

适用与失败边界：轻量覆盖安装体积、启动耗时、空闲资源及实际负载响应；不以采用某技术框架作为达标证据。当前未承诺统一的 MB、毫秒或帧率阈值。交付时记录测试设备、系统、版本、数据规模、加载上限和上述测量结果，供判断与后续量化；不得将未测数据写成成绩。

验收：

- 在可访问本地数据库但无法访问互联网的环境中，能够启动并完成基础查询、编辑与结构管理。
- 以对象数量和记录数量均超过默认加载上限的数据集操作，确认不会自动无限读取；加载期间仍能切换标签、输入文本和提交取消请求。
- 反复打开并关闭查询标签后，没有仍持续执行的孤立查询或隧道；对可能保留的连接显示实际状态。
- 交付记录包含三平台启动、空闲内存及安装体积实测，以及大对象列表、大结果集场景的响应表现；未达到无阻塞操作行为时，不以包体小为由判定通过。

## 不做事项

### R20 不包含 AI 功能

行为：首版不提供自然语言生成 SQL、AI 对话或自动代理执行数据库操作。

适用与失败边界：普通语法高亮、确定性补全和数据库错误展示属于首版能力，不归为 AI 功能。

验收：首版功能入口、配置和交付清单不包含模型配置、AI 对话或代理执行流程。

### R21 不包含云同步与团队权限平台

行为：首版不提供云端连接/历史同步、共享工作区、应用账号体系或团队角色管理。

适用与失败边界：数据库本身的账号权限、远程连接和 SSH 认证仍按 R3–R5 支持；不得据此扩展为应用级团队服务。

验收：无应用账号也可使用核心功能；不存在必须由云端工作区授权才能访问本地功能的流程。

### R22 不包含 NoSQL 数据库

行为：首版不提供 Redis、MongoDB 等 NoSQL 数据源连接和专用管理界面。

适用与失败边界：已支持关系数据库中的 JSON 字段可作为字段值浏览，不据此承诺 NoSQL 管理能力。

验收：连接类型与兼容矩阵不将 NoSQL 数据库列为支持对象。

### R23 不包含复杂关系图与可视化建模

行为：首版不提供 ER 图编辑、模型驱动建库或可视化联表查询设计器。

适用与失败边界：R6 的结构查看、R15 的外键表单仍在范围内，不扩展为图形建模工具。

验收：通过表单即可完成约定的结构管理，无图形建模模块被列为首版交付要求。

### R24 不包含数据库备份恢复

行为：首版不提供完整数据库备份、恢复、迁移或定时备份流程。

适用与失败边界：R17 的 CSV 导出和用户明确执行的 SQL 不等同于备份恢复产品能力；不将导出结果宣传为可完整恢复数据库的备份。

验收：导出说明标明其数据范围；首版没有备份恢复入口与完成承诺。

### R25 不包含运维监控

行为：首版不提供服务器健康看板、慢查询平台、会话治理、自动索引优化或告警调度。

适用与失败边界：当前操作的耗时、结果、错误和取消属于日常客户端反馈，按 R8 保留。

验收：首版可以反馈当前查询状态，但不将后台持续采集或运维监控作为使用前提或交付内容。

## 来源

- 本次需求对话：用户明确要求简单、轻量、高颜值、跨平台 SQL GUI；选择完整管理型、MySQL/MariaDB/PostgreSQL/SQLite 及内置 SSH，随后授权命名和生成文档。支持 R1–R19 的范围；此前提交的一屏摘要提供默认边界与 R20–R25 的排除方向。
- [TablePlus 官方功能](https://tableplus.com/)：变更预览、安全模式、行内编辑和快捷导航，支持 R6、R11、R16、R18 的体验取舍。
- [Beekeeper Studio 官方介绍](https://www.beekeeperstudio.io/)：跨平台 SQL 编辑、数据与结构管理的产品现状，支持 R2、R7、R9–R15 的基础能力判断。
- [Beekeeper Studio 大规模结构补全问题 #4492](https://github.com/beekeeper-studio/beekeeper-studio/issues/4492)：特定版本的用户报告，支持 R7、R19 纳入元数据规模与界面响应边界，不作为当前版本整体性能结论。
- [Antares 性能反馈 #942](https://github.com/antares-sql/antares/issues/942)：特定场景的用户反馈，支持 R19 同时观察启动与实际操作表现。
- [Antares 界面建议 #714](https://github.com/antares-sql/antares/issues/714)：查表、字体与界面占用相关反馈，支持 R6、R18 的可用性方向，不表示竞品当前仍缺少这些能力。
- [DbGate 官方介绍](https://dbgate.org/)：多平台及广泛管理能力的产品参照，支持 R20–R25 对首版功能边界的取舍。

## 非阻塞未知

- 名称可用性：尚未核验“澄库”“RillSQL”的商标、域名和商店名称；影响公开发布时的品牌使用，不影响以该名称形成需求与原型。
- 精确兼容环境：尚无指定系统/数据库版本和 CPU 架构清单；R2 已确定三平台与数据库范围，并要求交付时提供实际验证矩阵，不宣称支持全部历史环境。
- 性能基线：尚无指定硬件、数据集和数值预算；R19 已规定可观察的响应、加载和测量要求，因此可继续验证，不将没有依据的性能数字列为已承诺验收阈值。
