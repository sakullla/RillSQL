# 需求：日常工作台可用性

日期：2026-10-15

## 一屏摘要

- 目标：在现有四种引擎上，让写 SQL、看计划、改可定位的结果、导入导出和保存查询能连续完成（R1–R7）。
- 使用者：日常开发和数据分析人员，在 PostgreSQL、MySQL、MariaDB、SQLite 上查数、改数和搬走当前结果。
- 范围：字段补全、SQL 格式化、不改数据的执行计划、可定位查询结果的修改、向已有表导入 CSV/JSON、导出 JSON 与 INSERT、按名称保存查询（R1–R7）。
- 关键行为：补全只使用当前目标已读到的字段；改数据和导入都先预览再写入；计划、格式化和打开保存的查询都不执行写入（R1–R5、R7）。假设：导入不从文件建表；计划不收集实际执行耗时。
- 成功标准：能靠字段补全写出查询，看到计划且数据不变，改完可定位结果后重新读到新值，并按同一行范围导出 JSON 或 INSERT（R1、R3、R4、R6）。
- 不做事项：新引擎、ER 图、结构对比、生成式 AI、整库备份还原、IDE 级语义分析与重构（R8–R12）。

## 完整需求

### R1 按当前目标补全字段

行为：查询编辑器在当前执行目标已连接、且该库的表或视图字段已经读到时，补全列出这些字段。在已读到的表或视图名后输入点号时，列出该对象的字段。关键字和已读到的表、视图名仍然出现。

适用与失败边界：适用于 PostgreSQL、MySQL、MariaDB、SQLite 的当前执行目标。未选择目标、连接不可用、对象或字段尚未读到、或读取失败时，不提供这些字段名，并显示字段不可用的原因；已有关键字和已读到的对象名仍可补全。不解析别名、联接或子查询来推断字段。

验收：

- 当前目标已读到表 `orders` 的字段 `status` 时，在 `orders.` 后触发补全，列表中出现 `status`。
- 未选择执行目标时触发补全，列表中没有字段名，并可见字段不可用的说明。
- 某张表的字段读取失败时，补全不出现该表的猜测字段名，并可见失败原因。

### R2 格式化 SQL

行为：使用者可以格式化整篇编辑器内容，或只格式化当前选中的文本。格式化调整关键字大小写、缩进和换行；标识符、字符串、数值和注释的文本保持不变。

适用与失败边界：只改变编辑器中的文本，不连接数据库，也不执行语句。选中内容或全文无法安全格式化时，原文本保持不变，并显示无法格式化的原因。格式化选区时，选区以外的文本保持不变。

验收：

- 对一篇含多余空白的 `SELECT` 执行格式化后，关键字和缩进被整理，其中的字符串字面量和注释文本与格式化前一致。
- 文本含未闭合引号时执行格式化，编辑器内容与格式化前一致，并可见无法格式化的原因。
- 只选中多语句中的一条并格式化后，未选中的语句文本保持不变。

### R3 查看不改数据的执行计划

行为：使用者对“即将执行的语句”请求执行计划。语句选择与执行 SQL 相同：有选区时使用选区，否则使用光标所在语句。结果以可读的计划文本或表格展示。

适用与失败边界：适用于四种引擎的已连接执行目标。请求计划不写入、不删除数据，也不收集实际执行耗时。未选择目标、目标不可用、语句为空，或引擎拒绝生成计划时，显示原因，不展示成功的计划。多语句一次请求时，只对当前这一条生成计划。

验收：

- 对已连接目标上的一条 `SELECT` 请求计划后，可见该引擎返回的计划内容；请求前后，该语句所读表的行数不变。
- 未选择执行目标时请求计划，可见需要选择目标的说明，且没有成功计划。
- 引擎返回计划错误时，可见该错误；请求前后相关表的数据不变。

### R4 在能定位的查询结果里修改数据

行为：查询结果中的一行能够唯一对应到一张基表的已有行时，使用者可以修改单元格或标记删除该行。变更先暂存，预览确认后才写入；提交失败的行显示原因。提交成功后，按同一语句重新读取可见新值。

适用与失败边界：沿用表数据的定位规则：视图只读；缺少能够唯一确定行的键时，不能修改或删除已有行。联接、聚合，或结果无法唯一对应到一张基表一行时，单元格保持只读并显示原因。未确认前关闭或放弃暂存时，数据库不变。查询结果里不新增行；新增仍在表数据中完成。

验收：

- 一条单表 `SELECT` 的结果包含该表主键时，修改一个单元格、预览并确认后，重新执行该查询能看到新值。
- 对联接结果或缺少主键的结果尝试修改时，可见不能唯一确定行的原因，数据库中的原值不变。
- 视图查询结果尝试修改时，可见只读原因，数据库不变。
- 确认提交时某一行被数据库拒绝，该行可见失败原因，同一次暂存中尚未成功的其他修改不显示为已成功。

### R5 把 CSV 或 JSON 导入已有表

行为：使用者选择当前连接中的一张已有表，导入 CSV 或由对象组成的 JSON 数组。写入前展示字段对应和将写入的行，确认后才写入。完成后显示写入行数；有失败行时逐行显示原因。

适用与失败边界：只写入已有表，不从文件创建表，也不替换整个数据库。文件不是 CSV 或对象数组、必填字段没有对应列、或使用者在确认前取消时，不写入任何行并显示原因。某一行写入失败时，导入结果不能显示为全部成功。未提交的表数据暂存不参与导入。

验收：

- 向一张已有表确认导入 2 行与列名对应的 CSV 后，该表新增这 2 行，并可见写入行数为 2。
- 导入前取消，该表行数不变。
- 必填列没有对应字段时不能开始写入，并可见缺列原因。
- JSON 数组中有一行类型不被该列接受时，可见该行的失败原因，导入不显示为全部成功。

### R6 把当前数据导出为 JSON 或 INSERT 语句

行为：表数据和查询结果除现有 CSV 外，可以按同一次选择的行范围导出 JSON 数组，或导出这些行的 `INSERT` 语句。空值在两种文件中都保持为空值。导出前说明这不是数据库备份。

适用与失败边界：沿用 CSV 的行范围：已读取的部分结果保持部分结果；查询结果的全量导出只重新执行一条 `SELECT`。表上尚未提交的修改不进入文件。取消保存不产生导出任务。写入失败时不显示成功，且不破坏保存位置上已有文件的原内容。`INSERT` 只包含导出的行，不包含建表、索引或整库脚本。

验收：

- 将一张表已读取的 2 行导出为 JSON 后，文件是包含这两行字段的数组，其中的空值仍为空值。
- 将一条 `SELECT` 的已读取行导出为 SQL 后，文件包含对应的 `INSERT` 语句；导出说明中可见这不是数据库备份。
- 对非 `SELECT` 语句请求全量导出时，导出不开始，并可见只有 `SELECT` 可以全量导出。
- 表中有未提交修改时导出，文件内容与数据库中已提交的数据一致，不包含未提交修改。

### R7 保存查询并在不执行的情况下打开

行为：使用者可以为当前编辑器中的 SQL 命名并保存，同时记住当时的执行目标。保存列表可以按名称找到该查询，打开到查询标签，并可以重命名或删除。打开只载入 SQL 和可用的目标，不执行。

适用与失败边界：保存和打开都不执行 SQL，也不写入数据库。原连接已删除时，打开后载入 SQL，并要求重新选择执行目标。删除前可以取消；取消后该查询仍在列表中。查询历史仍是执行记录；保存查询不替代历史，历史中的“载入且不执行”保持不变。

验收：

- 将当前 SQL 保存为“日报”后，从保存列表打开，编辑器中出现同一 SQL，且这次打开没有新增一条成功的执行历史。
- 原连接已删除时打开该查询，编辑器中仍有 SQL，并可见需要重新选择执行目标；此时不执行。
- 删除“日报”时取消，列表中仍有“日报”。确认删除后，列表中不再有“日报”，编辑器里已打开的文本保留到使用者自己关闭为止。

## 不做事项

### R8 不增加数据库引擎

行为：连接引擎仍只有 PostgreSQL、MySQL、MariaDB、SQLite。

适用与失败边界：本需求不加入其他数据库或非关系型数据源。现有四种引擎的连接、TLS 和 SSH 行为保持可用。

验收：

- 新建连接时可选引擎仍只有这四种。

### R9 不做 ER 图和结构对比

行为：不提供 ER 图，也不提供库、模式或表结构之间的对比与差异脚本。

适用与失败边界：现有单表结构查看和带预览的结构修改保持可用。本需求不把它们扩展成图或跨库对比。

验收：

- 界面中没有 ER 图入口，也没有结构对比入口。

### R10 不做生成式 AI

行为：不提供根据自然语言生成、改写或解释 SQL 的助手。

适用与失败边界：补全、格式化和执行计划都来自已读到的对象元数据和引擎自身的计划，不调用生成式服务。

验收：

- 界面中没有生成、改写或解释 SQL 的 AI 入口。

### R11 不做整库备份与还原

行为：不提供整库备份、还原，或用 SQL 转储把整个数据库迁到另一台服务器。

适用与失败边界：R5 和 R6 只处理当前表或当前结果的数据文件。导出说明仍表明文件不是数据库备份。

验收：

- 导入和导出不能选择“备份整个数据库”或“从转储还原整个数据库”。

### R12 不做 IDE 级 SQL 分析与重构

行为：不提供执行前的语义错误检查、索引建议、重命名重构，或跨语句的结构改写。

适用与失败边界：R1 的字段补全和 R2 的文本格式化到此为止。别名、联接和子查询的语义推断不在本需求内。

验收：

- 编辑器不在执行前标出语义错误，也没有重命名列或提取查询的重构入口。

## 非阻塞未知

- 保存的查询要不要分组：不影响 R7。当前按名称列表保存、打开和删除即可交付。
- 各引擎计划输出的列名不同：不影响 R3。交付物只要可读，且请求计划不改变数据。
- 单次导入的行数上限没有给定：不承诺具体数字。R5 只要求确认前可见将写入的内容，失败行可见，且不能把部分失败显示为全部成功。
