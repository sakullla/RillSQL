# RillSQL 数据库工作台重做

## 使用者与任务

设计依据是仓库中真实存在的四种 SQL 引擎、连接与环境管理、SQL 编辑器、数据编辑、结构变更和导出流程。以下是据此整理的使用角色与任务假设，不冒充用户访谈结论。

| 使用者 | 最在意的事 | 对应设计 |
| --- | --- | --- |
| 日常开发者 | 迅速找到表、执行 SQL、切换上下文而不丢工作 | 真实连接首页、带目标的新查询、对象树、持续挂载的工作区、全局命令入口 |
| 数据分析人员 | 看清结果、查找值、复用查询、导出 | 可调编辑器与结果区、多语句结果标签、虚拟表格、行号、排序方向、完整值查看器、历史预览 |
| 维护数据库的开发与运维人员 | 确认连接、库、环境与变更影响 | 连接清单的地址/认证/状态列、引擎与环境筛选、目标环境标签、结构摘要、保留提交前预览 |
| 本地 SQLite 使用者 | 少配置，打开文件即开始 | 首页文件入口、文件选择只消费一次、本地文件与服务器连接分别呈现 |

## 页面变化

- 工作台：从居中的欢迎卡片改为可工作的数据库入口。展示真实连接、会话状态、直接进入对应数据库的查询，以及可点击的快捷操作。
- 框架与对象树：深色侧边导航与青绿色操作色，浅深主题共用层次。连接名称与状态分行；当前库标签缩短。窄窗口默认收起对象树，显式侧栏按钮可打开抽屉并点击遮罩关闭。
- 连接管理：以可扫描的连接清单替代大卡片。引擎、环境和文本筛选可组合。已连接状态读取现有会话；打开连接直接进入带执行目标的查询。
- SQL：执行目标在左、执行动作在右；编辑器/光标位置/结果工具栏明确分层。分隔条支持拖动和方向键调整，多语句结果直接切换。语法色随主题变化。
- 数据与结果：等宽内容、固定表头、交替行底色。两类表格共用按实际密度测量的虚拟行窗口，避免滚动位置错位。查询结果支持完整值查看与复制；数据表键盘选格可以跨越可见窗口。
- 表结构：表名、上下文、字段及索引数量先呈现，再进入字段、索引、外键与删除操作。编辑字段使用表格化输入，变更仍经过原有预览流程。
- 历史：筛选、按日期的紧凑记录与 SQL 详情并列。每页 30 条，但筛选覆盖全部已加载记录；载入 SQL 不执行；清空历史有可取消的明确确认。
- 设置：按外观、数据读取、本地数据分区并提供跳转。导出、连接编辑、SSH、快捷键和命令面板使用统一视觉令牌与外壳。

## 性能

- 生产入口 JS 从 702.68 KB 降至约 161.15 KB，减少 77.1%。SQL 编辑器、数据表、结构、连接、历史和设置按需加载。原生窗口 API 仍为独立共享块，入口大小不等同于整个应用资源大小。
- 查询结果的大数组不再建立深层响应式代理；单元格显示值在可见窗口内一次计算。
- 同一查询最多只有一次状态轮询在途；启动时已经完成的查询不轮询；旧查询的迟到回复不覆盖新查询。
- 关闭已经完成的查询会释放缓存结果；切换功能页保留编辑器和工作区实例，避免重复创建编辑器或重新读取表数据。
- 10,000 行 × 12 列的合成结果在 1360 × 900 视口中只渲染 19 行。完整集合仍参与查找和排序，虚拟化不改变导出数据范围。

## 原生 CSV 导出修复

原生窗口中的已读取行曾使用浏览器 Blob 下载，并在未确认落盘时报告成功。现在导出先打开系统“另存为”，已读取的表格和查询结果通过 `export_write_loaded` 写入本地文件，不重新查询数据库；全量导出仍使用原有数据库流式路径。先写临时文件并同步，再替换目标文件，写入失败保留原目标。

取消保存选择不会启动任务，选择位置期间防止重复点击，对话框错误和写入失败都有可见提示。任务对象通过响应式代理更新，只有原生写入完成才显示成功；启动新导出不会更改其他正在执行的任务。

回归：`npm test -- src/export/native.test.ts` 覆盖保存选择、取消、重复点击、原生 IPC、完成状态及失败反馈；`cargo test --lib native_export::tests`（在 `src-tauri` 中运行）验证真实 Windows 文件写入、中文内容、覆盖文件和无效路径。系统对话框由组件测试模拟，尚未执行原生窗口的人工点击验收。
