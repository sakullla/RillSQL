# Technical Solution

仓库没有可复用实现，见 `01-exploration.md`。下面的选择由方案负责人作出。外部资料只说明约束，不把竞品功能抄进首版。

## ADR-1 桌面壳与进程边界

决定：应用是 Tauri 2 桌面程序。Rust 进程拥有连接、查询、元数据、结构变更、导出、SSH 和密钥。系统 WebView 里的 TypeScript 界面只发命令和展示状态。界面技术固定为 Vite、Vue 3 与 CodeMirror 6 的官方 SQL 支持（`@codemirror/lang-sql`）。

依据：

- 需求要求 Windows、macOS、Linux 上同一套核心能力，并且启动和基本编辑不依赖云登录（R2、R19）。Tauri 使用系统 WebView：Windows 为 WebView2，macOS 为 WKWebView，Linux 为 WebKitGTK。Windows 10 1803 及以后通常已带 WebView2，Windows 11 预装。
- 同形态的 Beekeeper Studio 是 Electron、Vue 与 TypeScript，社区版为 GPLv3。它证明这种产品可以用 Web 界面做 SQL 编辑和结果表，但它把浏览器运行时打进安装包。本需求把轻量当作产品目标，且没有数值门槛，因此不采用 Electron，也不把任何博客里的体积或内存数字写成验收线。
- Tauri 2.12 已放弃官方 Windows 7 支持。需求本来就不承诺全部历史系统，交付时记录实际系统与架构。
- CodeMirror 6 的 SQL 包提供方言与 schema 补全，许可证为 MIT。补全只使用当前连接已经读到的元数据。

不做：不内置约 127MB 的离线 WebView2，以免为了极少见的缺运行时机器放弃轻量。已安装 WebView 运行时的机器必须能离线完成 R19 的本地库场景。Linux 发行版若缺少 WebKitGTK，安装说明写明该依赖，不把启动失败显示成已连接。

许可证：仓库唯一提交包含完整 GPL-3 文本（`LICENSE`）。应用按 GPL-3 发布。Tauri、russh、keyring、CodeMirror，以及下面的 tokio-postgres、mysql_async，只在其许可证为 MIT 或 Apache-2.0 时引入。若确认时否定 GPL-3，依赖选择要重审。

## ADR-2 数据库驱动与 TLS

决定：SQLite 仍用 sqlx。它是本地文件，没有 TLS，也不走 SSH。远程 PostgreSQL 用 tokio-postgres，远程 MySQL 与 MariaDB 用 mysql_async。MySQL 与 MariaDB 仍是两种连接类型，连接后读取服务器版本并分别探测能力。用户 SQL 原样提交，不做 ORM。

传输地址和 TLS 身份是两个字段，不能写成同一个 host：

- `tls_server_name` 是用户配置的数据库主机名。开启验证时，证书校验和 SNI 只用这个名字。
- `transport` 是直连时的数据库主机和端口，或 SSH 转发器上的本机地址。回环地址只表示转发器的接入点，不能当作证书名称。
- 禁止为了让隧道连通而关闭主机名验证，或在验证失败后改用不验证的模式重试。

选用这两套远程客户端，是因为它们能表达上述分离，而 sqlx 的连接器把同一个 host 同时用于 TCP 目标和 TLS 校验：

- tokio-postgres 在同时设置 `host` 与 `hostaddr` 时，TCP 连接使用 `hostaddr`，TLS 校验使用 `host`。经 SSH 时，`host` 是数据库主机名，`hostaddr` 是转发器的 `127.0.0.1`，端口是转发器端口。
- mysql_async 的 `SslOpts::with_danger_tls_hostname_override` 用于“经隧道连接、连接用的主机名和证书主机名不同”的情况。经 SSH 时，TCP 连接到转发器，override 设为数据库主机名。不调用 `skip_domain_validation`，也不接受无效证书。这个 override 只更换被校验的名字，校验本身保持开启。
- 直连不使用 override，也不把 `hostaddr` 指到转发器。TCP 目标和 TLS 名字都是用户配置的数据库主机。

其它 TLS 规则：

- 远程库可关闭、要求加密，或要求验证。用户选择验证时使用指定 CA 或系统信任根，并按上面的 `tls_server_name` 做主机名校验。
- 用户要求加密或验证时，握手失败不得退回明文。sqlx MySQL 默认的 `Preferred` 会在加密失败后退回明文，因此远程连接不使用 sqlx。mysql_async 仅在明确提供 `SslOpts` 时启用 TLS；未提供表示用户关闭了 TLS，而不是握手失败后的退路。
- 客户端证书材料交给对应客户端的 TLS 配置。材料不可读、证书过期、不受信任或主机名不符时直接失败。
- SQLite 连接界面不出现 TLS 设置。
- rustls 只支持 TLS 1.2 和 1.3。若目标库只提供更旧的 TLS，连接失败并说明原因，不改用不验证的通道。

能通过的隧道验证至少包括：证书签发给数据库主机名时，经转发器连接成功；证书只签发给 localhost 或回环地址时，在开启验证的前提下失败。

能力差异至少单独处理：SQLite 外键默认可能未强制执行，界面显示 `foreign_keys` 状态；MySQL 存储引擎不支持外键时报告限制；不支持的索引或引用动作只展示已有信息，不生成声称可成功的变更。

## ADR-3 单跳 SSH

决定：远程连接可选一个 SSH 跳板。Rust 用 russh 做密码或私钥认证，私钥口令只在解锁时使用。一次数据库会话对应一个已认证的 SSH 会话。这个会话上的隧道是转发器，不是一条供所有数据库流量共用的 `direct-tcpip`。

转发器监听 `127.0.0.1` 的临时端口，并接受多条本地 TCP 连接。每接受一条，就向用户配置的数据库主机和端口新开一条 `direct-tcpip` 通道，再双向转发该本地连接的字节。通道的目标是数据库地址，不是 TLS 校验名，也不是跳板机自己的地址。查询、取消、元数据以及其它并发的数据库 TCP 连接各占一次 accept，因此各有一条通道。两条数据库协议流不共用一条通道，也不为了取消而等待原连接先断开。

断开这次数据库会话时关闭 SSH 会话、监听端口和全部通道。

主机密钥：首次连接展示指纹，用户确认后才保存。已保存指纹变化时停止，不自动接受新密钥。认证失败、隧道失败和数据库认证失败分成三段错误，日志不写密码、私钥或口令。

不做多跳、代理转发和企业单点登录。

## ADR-4 机密与本地状态

决定：连接配置、查询历史和已确认的主机密钥指纹放在本机应用数据里的一个 SQLite 文件。密码和私钥口令不进入该文件、普通日志或历史元数据。用户选择保存密码时写入操作系统凭据库：macOS Keychain、Windows Credential Manager、Linux Secret Service（`keyring` crate）。

凭据库不可用或写入失败时，连接仍可使用本次输入的密码，配置标记为未保存密码。删除连接配置不删除数据库或 SQLite 文件，并删除对应凭据项。历史只在用户再次执行时才提交 SQL。

## ADR-5 执行、取消与结果未知

决定：每个正在执行的语句占用一条可识别的会话。取消按引擎分别做，界面只有三种完成态：已请求、已确认取消、取消失败。查询完成或仍然成功都不是“已取消”。

- PostgreSQL 官方取消是另开一条连接发送 CancelRequest，而不是把取消字节写进正在执行的那条连接。服务器不直接回复是否成功，原查询可能已经结束；断开时，事务外的非 `SELECT` 仍可能在服务端提交。启用 SSH 时，这条取消连接必须再次连接转发器，从而打开另一条通道。取消的 TCP 目标与原查询相同，不能绕过隧道直接连数据库主机。等待原语句结束后再定性。
- MySQL 用另一条连接执行 `KILL QUERY`，并保留原连接。启用 SSH 时，这条连接同样独占一条新通道，并遵守 ADR-2 的 TLS 主机名规则。MariaDB 也支持 `KILL QUERY`，但不把 MariaDB 额外的 `HARD`/`SOFT` 或 `QUERY ID` 写成通用成功路径。
- SQLite 用 `sqlite3_interrupt`。官方说明它只在最早机会中止，临近完成的语句可能跑完；事务内的写入被中止时会回滚该事务。SQLite 没有 SSH，也不需要第二条网络连接。
- 丢弃客户端 future 或只关闭查询连接的本地一端，都不是远程取消。禁止据此标记已取消。
- 断连后无法确认写入是否完成时标记结果未知，不自动重放。
- 用户明确执行的多条 SQL 按顺序提交，某条失败后停止后续语句，并保留前面已完成的结果。手写 SQL 不承诺自动回滚。

执行期间 WebView 仍可切换标签和编辑其他草稿。长任务在 Rust 异步任务中运行，不阻塞界面线程。

## ADR-6 结构变更

决定：可视化建表、改字段、索引、外键和删表都先生成目标连接上的 SQL 与影响说明。用户取消则不连接执行。确认后逐步执行，并报告成功、失败、部分完成或结果未知。

方言：

- PostgreSQL 的 `BEGIN` 把后续语句放进同一事务，失败可以 `ROLLBACK`。预览仍展示实际 SQL；不把这一点宣传成所有数据库都能回滚。
- MySQL 的 DDL 会隐式结束当前事务。官方同时说明 atomic DDL 不是 transactional DDL，不能和前后语句合成一个可整体回滚的事务。多步结构变更按步报告，中途失败不声称已全部回滚。
- SQLite 直接支持的变更限于重命名表、重命名列、加列、删列，以及 3.53.0 起的设置或去掉 `NOT NULL`。加列不能带主键或唯一约束，`NOT NULL` 必须有非 NULL 默认值。删列在列被索引、主键、外键、触发器或视图引用时失败。其余变更走官方的 12 步重建：先在事务外关闭外键强制，创建新表，复制数据，删除旧表，再把新表改回原名，重建能够可靠保留的索引、触发器和视图，然后 `foreign_key_check`。禁止先把旧表改成临时名再复制的错误顺序。
- 重建若不能可靠保留现有数据、索引或约束，提交前阻止并说明原因。删除表只删除预览中的对象，不隐式级联删除其他业务对象。

## ADR-7 浏览、编辑与导出

决定：对象列表、结果行和大字段都有默认上限，界面显示已加载数量和截断。继续读取是单独动作。筛选和排序标明作用范围，页内排序不显示成全表排序。`NULL` 与空字符串分开展示、复制和导出。

基础表浏览始终提供新增。新增不需要定位已有行，因此没有主键或其它唯一约束的基础表也可以插入。修改和删除只在该行能用主键或其它可靠唯一约束定位时可用；定位不到时禁用这两项。插入后仍无法唯一定位的新行保持不可修改、不可删除。联表和聚合结果首版不提供新增、修改或删除。

CSV 在开始前声明范围。只导出已加载数据时必须这样标明，文件名带“（部分）”。对查询结果做全量导出时，只允许当前语句是 SELECT，并在开始前说明将重新执行这条语句；非 SELECT 不能按全量导出。导出按流写入，完成时报告实际行数。路径不可写、读取失败或用户取消时不得显示成功；失败保留已写入部分并说明残留文件，用户取消则删除未完成文件。

表数据的筛选和排序用结构化条件生成服务器端 SQL，不提供手写 WHERE 片段。匹配行数只在用户要求统计时执行 COUNT。数据与结构变更逐条自动提交，失败即停；已经成功的语句不撤销，即使引擎支持事务，也不默认包成一个整体事务。

## ADR-8 首版边界

不实现 R20–R25：没有模型配置或 AI 入口，没有应用账号和云同步，不连接 NoSQL，没有 ER 图或可视化查询设计器，没有备份恢复，没有监控、告警或会话治理。JSON 字段只作为关系库中的值显示。

## ADR-9 按原型实现界面

决定：首版的信息架构、视觉和交互以 `docs/prototype/` v0.2 为准，不另做一套界面。依据是 `docs/prototype/README.md`，样式令牌在 `docs/prototype/styles/app.css`，行为可对照同目录的 `index.html` 与 `scripts/`。

原型只约束产品和交互，不改变 ADR-1 的运行时。它用原生 HTML 做离线评审，正式界面仍是 Tauri 2 里的 Vite、Vue 3 和 CodeMirror 6。原型的内存示例数据、简化 SQL 解析、textarea 编辑器和未虚拟化表格不进入产品。表格要虚拟滚动。编辑器使用 CodeMirror 6。

产品里不出现原型右上角的“原型评审”面板，也不读取 `?scenario=`、`?demo=` 这类评审参数。

界面按 README 的组件边界实现：`AppShell`、`ActivityRail`、`Explorer`、`TabBar`、`QueryTab`、`DataGrid`、`TableTab`、`ChangePreviewDialog`、`ConnectionDialog`、`ExportDialog`、`TaskCenter`、`CommandPalette`、`StatusBar`。视觉使用 README「视觉规范」里的令牌、字号、密度、布局和窄窗口规则。颜色不能作为状态或环境的唯一区分。

快捷键在按钮、菜单和帮助里可见。桌面版使用平台习惯关闭标签和新建标签：Windows 与 Linux 为 Ctrl+W、Ctrl+T，macOS 为 ⌘W、⌘T。原型因浏览器占用而使用的 Alt+W、Ctrl+Alt+N 只属于评审页。

数据提交、全量导出、表筛选和 COUNT 按原型固定在 ADR-7。原型文末其余待确认点也按原型已经采用的做法固定：

- 未执行的 SQL 草稿只在当前会话中。关闭前按原型确认。重启不恢复草稿。
- 连接可以带环境标签：开发、测试、生产、本地。标签写入本机连接配置，始终有文字，颜色只作辅助。它不表示权限、云环境或账号。
- 初始加载批量为结果 100 行、大字段预览 1 KB、对象列表每批 100 个，设置中可改。这是批量上限，不是 R19 的性能验收数字。
- SQLite 的设置或去掉 NOT NULL：捆绑库低于 3.53 时走原型里的重建预览；达到 3.53 且属于官方可直接修改的子集时，预览为对应 ALTER，不套 12 步。其余超出直接 ALTER 能力的变更仍按 ADR-6 和原型的重建或阻止流程。

## 失败时用户看到什么

| 情况 | 行为 |
| --- | --- |
| 认证、网络、文件权限或 TLS 失败 | 保持未连接，展示原因，配置可改 |
| 隧道中的证书与数据库主机名不符 | 验证失败，不改用 localhost 身份，也不关闭主机名验证后重试 |
| 取消连接开不出新的 SSH 通道 | 取消失败，原查询连接保持原状态 |
| 主机密钥变化 | 阻止连接，直到用户明确处理 |
| 凭据库不可用 | 允许本次连接，不把密码写入普通配置 |
| 取消没有得到引擎确认 | 保持“已请求”或“取消失败”，不改记为已取消 |
| 断连且写入结果不明 | 标记未知，不重放 SQL |
| 结构变更中途失败 | 列出已执行步骤和未执行步骤 |
| SQLite 无法安全重建 | 不执行，说明缺哪一类保留保证 |
| 元数据或结果加载失败 | 显示错误，不用空列表冒充成功 |

## 需求覆盖

R1–R19 的界面落在 `docs/prototype/README.md` 的覆盖表和 ADR-9。R4 的主机名验证在 SSH 下仍针对数据库主机名。R5 的隧道可同时承载查询和取消。R11 的新增不依赖行标识，修改和删除才依赖。R2 的版本矩阵和 R19 的实测记录是交付物，不在方案里预填数字。R20–R25 保持不做。

## 仍开放、但不阻塞方案的点

- 交付时才能填写的系统、架构和数据库版本。
- `sqlite3_interrupt` 是否能经当前 sqlx 连接直接调用；不能则对同一句柄做最小 FFI。这是实现细节，不改变取消语义。
- 名称的商标、域名和商店可用性。需求已把它列为非阻塞未知。
